このバージョンでは「カスタム (System One 意思決定モデル)」の入口を追加し、LAN 内やサードパーティの Jev / Clef 意思決定モデルのエンドポイントを手動で model-jev に接続できるようにしました。あわせて、長時間のストリーミング生成が 10 分で切断される問題を修正しました。アップグレード後も既存のサブスクリプションの動作は変わりません。

## 新機能
- **カスタム System One 意思決定モデルの入口**：サブスクリプションの追加時に、プロバイダのドロップダウンの「カスタム」グループで「カスタム (System One 意思決定モデル)」を選び、Base URL、エンドポイントのパス、API Key、Jev モデルを手動で入力します。LAN 内の別マシンの Ollama、自前のゲートウェイ、その他のサードパーティのホスティングに向いています。
  - サブスクリプションは `model-jev` にのみ割り当てられ、リクエストはプロトコル変換せずにそのまま転送します。
  - 認証方式は `Authorization: Bearer` と `x-api-key` から選べます。上流が API Key を検証しない場合は任意の値を入力してください。
  - Jev モデルは必須です：カスタムのサブスクリプションにはフォールバック先のサンプルモデルがないため、空欄やスペースのみでは保存できず、編集時にも空にできません。組み込みの System One サブスクリプションの Jev モデルは、これまでどおり空欄にできます。
  - ターミナル UI の新規作成ウィザードでも利用でき、このプロトコルを選ぶとフォームには Jev モデルの行が 1 つだけ表示されます。
  - `model-jev` へのリクエストでは、Jev モデルもサンプルモデルもないサブスクリプションはスキップされ、ほかのサブスクリプションが処理を続けます。すべて利用できない場合は理由を明記した 503 を返し、リクエスト全体を 400 で失敗させることはなくなりました。

## 修正
- **長時間のストリーミング生成が 10 分で切断される問題**（#59、報告してくれた @WayneOffice さんに感謝）：これまで上流へ転送するリクエストには合計 600 秒の時間制限があり、10 分を超えて生成し続けるストリーミング応答が途中で切断されていました。現在はアイドルタイムアウトに変更し、上流から 600 秒続けてデータが届かない場合にのみ切断するため、出力が続いている長い生成は制限されなくなりました。非ストリーミングのリクエストは引き続き最大 600 秒待機します。
  - タイムアウト時のエラーは「error decoding response body」から、上流データの待機がタイムアウトして接続を閉じたことを示す内容に変わりました。
